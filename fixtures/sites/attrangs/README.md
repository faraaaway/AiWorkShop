수집 일시: 2026-11-27 23:00경 (KST). 로그인 없이 받은 공개 페이지 원본 HTML이다.

| 파일 | 주소 | 내용 |
|------|------|------|
| `home.html` | `https://attrangs.co.kr/` | 첫 화면. 메뉴에 `<a href="/shop/list.php?cate=2357">블프특가🧨</a>` |

## 받은 방법 (Obscura가 아님)

이 PC에 Obscura가 설치돼 있지 않아 **`curl`로 단순 GET**(브라우저 User-Agent, 요청 사이 3초 이상 대기)해서 받았다.
`obscura fetch --dump original`과 같은 "렌더링 없는 원본"이지만 Obscura로 받은 것과 바이트가 같다는 확인은 하지 못했다.
Obscura를 설치한 뒤 아래 명령으로 같은 구조가 오는지 한 번 확인할 것.

```powershell
& $env:OBSCURA_PATH --stealth --obey-robots fetch "https://attrangs.co.kr/shop/list.php?mode=loadHTML&page=1&limit=48&cate=2357" --dump original
```

`robots.txt`(2026-09-01 수정본)는 `Allow: /`이고 `/shop/list.php`는 `filterKeyword=`와 `cate=2620`만 막는다.
위 세 주소와 상품 페이지(`/shop/view.php`)는 허용된다.

## 확인한 동작

- 스크롤 주소는 헤더 없이 GET만으로 응답한다. 화면은 `limit=16`으로 부르지만 `limit=48`도 그대로 적용된다.
- `limit=48`일 때 10쪽은 빈 응답(0바이트)이었고, `limit=16`의 12쪽에는 상품이 있었다 → 행사 상품은 192~432개 사이.
- 목록 순서는 요청할 때마다 조금씩 바뀐다(인기순). 쪽 사이에 겹치거나 빠지는 상품이 있을 수 있어 수집기는 상품 번호로 중복을 없앤다.
- 목록·행사 페이지·상품 페이지 어디에도 **행사 기간이 없다** → `endsAt`, `event.endsAt`은 `null`.
- 수집 당시 목록에 품절 상품이 없어 품절 표시(마크업)는 확인하지 못했다.

- 링크는 5개 모두 해당 상품 페이지로 열렸고(HTTP 200), 상품 페이지는 모두 판매 중(`InStock`)이었다.
- 할인율 1%p 차이는 사이트 안에서 목록(49%)과 상품 페이지(50%)의 반올림이 다른 것이다. 수집기는 목록 표시값을 그대로 넣는다.
- 상품명은 목록 쪽에 `[1만5천장 돌파✨]` 같은 머리말이 붙는 경우가 있다(151412). 목록 표시를 그대로 넣는다.
- 상품 페이지의 구조화 데이터는 5개 모두 브랜드를 "아뜨랑스"로 적지만, 목록에는 브랜드 표기가 없고 사이트에 다른 브랜드
  (스무레·프롬 등)도 있어 `brand`는 `null`로 둔다.
